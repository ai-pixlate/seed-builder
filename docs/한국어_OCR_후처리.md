# 한국어 OCR 후처리 — 덩어리 묶기

한국 상세페이지(올리브영) 이미지를 OCR 한 결과를, **붙어 있는 글끼리 한 덩어리(블록)**로 묶는 코드입니다.
OCR 은 다시 하지 않고, 이미 읽은 글자 상자(텍스트 + 좌표)만 정리합니다.
번역 파이프라인에서 "한국어 원문 문장 단위"를 만드는 단계로 씁니다.

| 파일 | 하는 일 |
|---|---|
| `korean/kr_ocr_blocks.py` | OCR 줄 CSV → 덩어리 CSV. 카드형 배치·수치 카드·각주·글머리·제목/설명을 구분해 묶음 |

영어(아마존) 이미지의 순서 정리·글자 보정은 `docs/OCR_후처리_보정.md` (`amazon/reorder_ocr_v2.py`) 를 보세요. 한국어는 배치가 달라서 따로 만들었습니다.

---

## 1. 왜 따로 필요한가

한국 상세페이지는 **카드형 배치**가 많습니다.

```
 ┌─ Point 1 ─┐ ┌─ Point 2 ─┐ ┌─ Point 3 ─┐
 │ 8K급      │ │ 10중      │ │ 퍼프맛집   │
 │ 모공순삭   │ │ 히알루론산 │ │ 전용퍼프   │
 └───────────┘ └───────────┘ └───────────┘
```

OCR 결과를 **읽는 순서상 바로 앞 줄하고만** 비교해서 이어 붙이면, 가로로 읽을 때 바로 앞 줄이 **옆 카드의 글**이 됩니다.

- 잘못된 결과: `Point 1 Point 2 Point 3 ‖ 8K급 10중 퍼프맛집 ‖ 모공순삭 히알루론산 전용퍼프`
- 원하는 결과: `Point 1 8K급 모공순삭 ‖ Point 2 10중 히알루론산 ‖ Point 3 퍼프맛집 전용퍼프`

첫 검수(이미지 50장)에서 이 방식은 **bad 9장 · partial 4장**이었습니다.

## 2. 어떻게 묶나

이미지 안의 **모든 글자 상자끼리** 비교해서, 서로 붙어 있으면 같은 덩어리로 묶습니다 (union-find 연결 요소).

**같은 덩어리로 보는 경우**

| 규칙 | 조건 (설정값) |
|---|---|
| 위아래로 붙음 | 세로 간격 ≤ 작은 글자 높이 × `STACK_GAP`(0.9), 그리고 가로로 겹침(좁은 쪽 기준 ≥ `MIN_X_OVERLAP` 0.2) 또는 가운데 정렬(가로 중심 차 ≤ 넓은 쪽 너비 × `CENTER_TOL` 0.25) |
| 같은 줄에서 붙음 | 세로 중심 차 ≤ 작은 글자 높이 × 0.5, 가로 간격 ≤ 작은 글자 높이 × `SAME_LINE_GAP`(0.4) |

**붙어 있어도 나누는 경우** (2차 검수에서 추가)

| 경우 | 규칙 | 예 |
|---|---|---|
| 큰 제목 ↔ 작은 주석 | 글자 크기 비 > `MAX_H_RATIO`(2.2) | |
| 제목 ↔ 설명 | 큰 쪽이 숫자 없는 글이고 크기 비 > `TITLE_H_RATIO`(1.5). **큰 숫자 + 작은 설명(수치 카드)은 묶음** | `눈가에 수분광 가득 하이드로겔 패치` ‖ `수분과 탄력을 빈틈없이 채워…` |
| 나란한 수치 카드 | 세로 간격을 **작은** 글자 높이 기준으로 | `9.23% 속수분개선` ‖ `134.16% 겉수분개선` |
| 각주 | `*`, `※`, `1)`로 시작하면 본문과 따로. 단 각주 아래 이어지는 줄은 각주에 붙임 | |
| 글머리 | `·`, `•`, `■`…로 시작하는 줄은 새 항목 | `·자연의 당근씨 오일…` ‖ `·무너진 피부 컨디션을…` |
| OCR 이 두 칸을 한 상자로 읽음 | `…합니다.눈썹빈곳을…`처럼 `다.` 뒤에 띄어쓰기 없이 이어지면 상자를 글자 수 비율로 나눔 | `STEP1 …잡아줍니다.` ‖ `STEP2 …채워줍니다.` |

**덩어리 안 · 덩어리 순서**
- 덩어리 안: 줄 단위로 위→아래, 줄 안에서 왼→오. 같은 줄 조각은 띄어 잇고, **줄과 줄 사이는 kiwipiepy 띄어쓰기 판단**으로 잇습니다. 한국어는 단어 중간에서 줄이 바뀌기 때문이에요. 문장 전체를 교정하면 `엑스폴리에이팅`이 `엑스 폴리 에이 팅`으로 쪼개지므로, **이어 붙이는 경계 앞뒤 8글자만** 판단합니다.
- 덩어리 순서: 위쪽부터. 세로 범위가 절반 이상 겹치는 덩어리끼리는 같은 행으로 보고 왼→오.

## 3. 실행

```
py -3.12 -m pip install kiwipiepy==0.23.2
py -3.12 korean/kr_ocr_blocks.py <입력 OCR 줄 CSV> <출력 덩어리 CSV>
```

- kiwipiepy 가 없으면 줄 사이를 항상 띄어 잇습니다 (경고 출력).
- 속도: 이미지 1,602장 · 글자 상자 48,563개 → 약 2~3분 (CPU).

### 입력 (OCR 줄 1개 = 1행, `utf-8-sig`)
| 열 | 필수 | 설명 |
|---|---|---|
| `image_id` | ✅ | 이미지 구분 |
| `text` | ✅ | OCR 이 읽은 글자 |
| `x1, y1, x2, y2` | ✅ | 글자 상자 좌표 (원본 이미지 기준, 똑바른 네모) |
| `confidence` | ✅ | OCR 신뢰도 |
| 그 밖의 열 (`goods_no`, `brand` …) | | 덩어리 첫 줄 값을 그대로 이어 받음 (`line_id`는 버림) |

### 출력 (덩어리 1개 = 1행)
| 열 | 설명 |
|---|---|
| `block_id` | `B000001`… |
| `image_id` + 입력의 다른 열 | |
| `block_order` | 이미지 안 읽는 순서 (1부터) |
| `text` | 이어 붙인 덩어리 글 |
| `line_count` | 묶인 OCR 상자 수 |
| `x1, y1, x2, y2` | 덩어리 전체 범위 |
| `confidence` | 묶인 상자 신뢰도 평균 |

## 4. 앞 단계: 한국어 OCR 설정 (참고)

이 코드의 입력은 아래 설정으로 만든 OCR 결과입니다. OCR 실행 코드는 이 브랜치의 `amazon/run_ocr.py`와 같은 구조이고, 다른 점만 적습니다.

| 항목 | 값 |
|---|---|
| 글자 위치 찾기 | `PP-OCRv5_server_det` (영어와 같음) |
| 글자 읽기 | `korean_PP-OCRv5_mobile_rec` (한국어 모델) |
| 신뢰도 하한 | 0.60 |
| 긴 이미지 | 한국 상세 이미지는 세로로 매우 길어(최대 약 25,000px) 통째로 넣으면 작은 글자를 놓칩니다. **높이 1,600px 띠로 260px씩 겹쳐 잘라** 읽고, 겹친 구간에서 두 번 잡힌 글자는 **자리가 50% 넘게 겹치면 신뢰도 높은 쪽만** 남깁니다 |

## 5. 검수 결과

올리브영 상세 이미지에서 무작위 50장씩 사람이 확인했습니다.

| 회차 | 방식 | 결과 |
|---|---|---|
| 1차 | 기존 "바로 앞 줄과 이어 붙이기" | 글자 인식은 좋음(다시 OCR 할 장 없음). **카드형 배치에서 묶음이 틀림: bad 9 · partial 4** |
| 2차 | 이 코드 (1차 문제 이미지 25장 + 새 이미지 28장) | 사용자 판단 "잘 가져온다". 메모 8건 중 6건을 '나누는 규칙'으로 반영 |

**남은 한계 (드물어서 그대로 둠)**
- 숫자 칸들이 아주 바짝 붙은 수치 그래프는 한 덩어리로 나올 수 있습니다.
- 큰 글씨 제목 규칙 때문에 `013 탠저린레드`(색상명)와 그 설명이 따로 떨어지는 경우가 있습니다.
- 제품 포장 위 글자(브랜드명·용량)도 덩어리로 나옵니다. 구분은 이후 단계에서 합니다.

## 6. 세로 · 기울어진 글씨 (시험했지만 쓰지 않기로 함)

지금 OCR 은 글자 위치를 **똑바른 네모로 잘라 가로로만** 읽습니다. 그래서 세로 글씨나 기울어진 글씨는 버려지거나 틀리게 읽힙니다.

- **시험:** 이미지 150장에서 세로·기울어진 조각 312개를 찾았습니다. 전체 글자의 약 6%예요.
  - 세로 글씨 → **90° 돌려 읽기**: 버려지던 72개 중 59개를 읽음
  - 기울어진 글씨 → **원근 변환으로 똑바로 펴서 읽기**: 69개를 새로 읽고, 54개의 오타를 바로잡음
  - 위아래로 한 글자씩 쌓은 한국어 세로 글씨는 "펼쳐 읽기"로도 잘 안 됨
- **전체 적용 (1,729장):** 1,910줄을 새로 얻었고, 그중 한국어는 150줄이었습니다(신뢰도 0.80 이상만).
- **검수 (한국어 50개):** 맞음 46 · 조금 틀림 2 · 버림 2. **읽기는 정확했지만 내용이 대부분 제품명·배지·용기 문구**였습니다(예: `독도로션`, `알러지테스트완료`, `용기재사용`, 그래프 축 이름). 홍보 문장은 거의 없었습니다.
- **결론:** 기존 OCR 이 홍보 문구를 충분히 잡고 있어서, **보충 OCR 은 파이프라인에 넣지 않습니다.** 코드도 이 브랜치에 올리지 않았습니다. 다만 나중에 포장 글자를 따로 다룰 일이 생기면, "90° 돌리기 / 원근 변환으로 펴기"가 효과가 있다는 점은 확인됐습니다.

## 7. 번역 파이프라인에서 쓰는 법

1. 한국어 상세 이미지 OCR → OCR 줄 CSV (4번 설정)
2. `korean/kr_ocr_blocks.py` → 덩어리 CSV
3. 덩어리 `text`를 번역 단위로 사용합니다. `block_order` 순서가 사람이 읽는 순서예요.
4. 용어집_문구는 덩어리 `text`로 벡터 검색합니다(같은 G, 적재여부=Y). 말투규칙과 함께 번역 모델에 참고로 넣습니다.
