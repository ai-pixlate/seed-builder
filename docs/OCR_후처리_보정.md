# OCR 후처리·보정

상세페이지 이미지에서 글자를 읽고(OCR), 읽는 순서를 정리하고, 자주 틀리는 글자를 보정하는 코드입니다.
12월 서비스용 아마존 최종 수집(Skin Care · Makeup · Hair Care, 이미지 23,568장)에 이 코드를 썼습니다.

| 파일 | 하는 일 |
|---|---|
| `amazon/run_ocr.py` | 이미지에서 글자 덩어리를 찾아 읽고 좌표와 함께 저장 (PaddleOCR PP-OCRv5) |
| `amazon/reorder_ocr.py` | 1차 순서 정리: 빈 틈으로 문단을 나눔 (XY-cut). `reorder_ocr_v2.py`가 불러서 씀 |
| `amazon/reorder_ocr_v2.py` | 2차·3차: 같은 줄 묶기, 겹친 글자 제거, 글자 보정 (`fix_chars`). **순서 정리는 이 파일을 쓰면 됨** |

## 1. 설치

Python 3.12 기준. 버전을 맞춰야 OCR이 동작합니다 (`requirements.txt`).

```
py -3.12 -m pip install -r requirements.txt
```

- `paddlepaddle==3.0.0`, `paddleocr==3.7.0`, `opencv-python==4.10.0.84`
- paddleocr 3.7의 기본 모델(PP-OCRv6)은 paddlepaddle 3.0.0에서 동작하지 않아서, 코드에서 **PP-OCRv5로 고정**했습니다.
- 모델 캐시는 `C:\paddlex_cache`에 둡니다. Paddle은 **경로에 한글이 있으면 모델 파일을 열지 못합니다** (Windows 사용자 이름이 한글이면 기본 위치에서 실패). 다른 위치를 쓰려면 `run_ocr.py`의 `CACHE_DIR`를 바꾸세요.

## 2. OCR 실행 (`run_ocr.py`)

### 입력 (작업 폴더 안)
- `out_images.csv`: 이미지 목록. 필수 칸은 `image_id`, `ocr_target`(`Y`인 행만 OCR). `asin`, `image_type` 등 다른 칸은 그대로 결과에 이어집니다.
- `images/`: 이미지 파일. 파일 이름이 `image_id`와 같아야 합니다 (`.jpg` `.png` `.webp` `.gif`).

### 실행
기본 작업 폴더는 `data/main/`입니다. 다른 폴더에서 돌리려면:

```python
import os, sys
sys.path.insert(0, "amazon")
import run_ocr                 # 불러오는 순간 data/main 으로 이동하므로
os.chdir("내/작업/폴더")        # 그다음 작업 폴더로 옮겨서
run_ocr.main()
```

### 출력
| 파일 | 내용 |
|---|---|
| `out_images_ocr.csv` | 이미지당 1행. `ocr_text`(읽은 순서 그대로), `ocr_line_count`, `ocr_avg_confidence` |
| `out_ocr_lines.csv` | 글자 덩어리당 1행. `text`, 좌표 `x1 y1 x2 y2`, `confidence` |
| `ocr_progress.json` | 진행 기록. 중간에 멈춰도 다시 실행하면 이어서 진행 |

### 설정
- 모델: `PP-OCRv5_server_det`(글자 위치 찾기) + `PP-OCRv5_mobile_rec`(글자 읽기). server_rec은 6배 느리고 오인식이 더 많아서 쓰지 않습니다.
- `MIN_CONFIDENCE = 0.60`: 신뢰도가 이보다 낮은 덩어리는 버립니다.
- 속도: CPU 기준 1초에 약 0.12~0.33장 (이미지 크기·글자 양에 따라 다름).

## 3. 순서 정리·보정 (`reorder_ocr_v2.py`)

OCR을 다시 돌리지 않고, 이미 읽은 결과만 정리합니다. 수만 장도 몇 분이면 끝납니다.

### 실행
```
py -3.12 amazon/reorder_ocr_v2.py <작업 폴더>
```
작업 폴더 안의 `out_ocr_lines.csv`, `out_images_ocr.csv`를 읽습니다.

### 출력
| 파일 | 추가되는 칸 |
|---|---|
| `out_ocr_lines_ordered.csv` | `block_id`(문단 번호), `reading_order`(읽는 순서), `text_clean`(보정한 글자) |
| `out_images_ocr_ordered.csv` | `ocr_text_ordered`(정리된 전체 글, 문단은 ` ‖ `로 구분), `ocr_block_count` |

- **원래 글자(`text`)는 바꾸지 않고**, 보정한 글자는 `text_clean`에 따로 담습니다. 언제든 원래 값과 비교하거나 되돌릴 수 있습니다.
- 글자 보정만 따로 쓰려면: `from reorder_ocr_v2 import fix_chars` → `fix_chars("SPF 5O")` → `("SPF 50", {"num_o"})`

## 4. 수정 이력

원칙: **확실히 틀린 것만 고치고, 애매하면 건드리지 않는다.** 일부 오류를 남기더라도 맞게 읽은 글자를 망가뜨리지 않는 것을 우선했습니다.

| 차수 | 날짜 | 고친 것 | 방법 |
|---|---|---|---|
| 1차 | 2026-09-04 | 좌우 칸 섞임 | 빈 틈(여백)으로 문단을 잘라 문단별로 읽기 |
| 2차 | 2026-10-12 | 같은 줄 단어 순서 | 세로 가운데가 글자 키의 절반 이내면 같은 줄로 묶고 왼쪽부터 읽기 |
| 2차 | 2026-10-12 | 겹친 글자 | 조건 3개가 모두 맞을 때만 한 글자 지우기 |
| 3차 | 2026-10-19 | 전각 글자, 숫자 속 o, 맨 앞 따옴표 | 확실한 모양만 바꾸기 |

### 1차 · 좌우 칸 섞임
- 문제: 글이 좌우 두 칸이면 "왼쪽 1줄 → 오른쪽 1줄 → 왼쪽 2줄 …"처럼 섞였습니다.
- 방법: 글자가 없는 세로·가로 여백 중 가장 넓은 곳으로 계속 잘라 문단을 나누고, 문단 하나를 다 읽은 뒤 다음 문단으로 넘어갑니다 (`GAP_RATIO = 0.8` × 줄 높이 이상의 여백).

### 2차 · 같은 줄 단어 순서
- 문제: 문단 안에서 위쪽 좌표만으로 정렬해서, 몇 픽셀 차이로 순서가 뒤집혔습니다. 예) Lip Stain Set → **Lip Set Stain**
- 방법: 상자의 세로 가운데가 글자 키의 절반 이내로 가까우면 같은 줄로 묶고, 줄 안에서는 왼쪽부터 읽습니다 (`order_lines`).

### 2차 · 겹친 글자
- 문제: 상자가 겹치면 앞 단어 끝 글자가 다음 상자 맨 앞에 한 번 더 읽힙니다. 예) **Deep o Hydration**, **choose e your**
- 방법: 아래 세 조건이 **모두** 맞을 때만 그 한 글자를 지웁니다 (`strip_stray`).
  1. 상자 맨 앞이 "한 글자 + 띄어쓰기"
  2. 같은 줄 바로 왼쪽에 붙어 있거나 겹친 상자가 있음
  3. 그 글자가 앞 단어 마지막 글자와 같거나 생김새가 비슷함 (p↔o, l↔1 등)
- 결과: 섞였던 19장 재확인 → 15장 good. 최종 수집에서 1,640건 제거.

### 3차 · 글자 보정 (`fix_chars`)
최종 수집 60장(카테고리별 20장) 검수 결과 **58장 good, 순서 문제 없음.** 검수에서 나온 문제를 전체 데이터(글자 덩어리 36만 개)에서 다시 확인하고, 안전한 3가지만 반영했습니다.

| 보정 | 예시 | 건수 | 바꾸지 않는 것 |
|---|---|---|---|
| 전각 → 반각 | TOＥ ＢRONZE → TOE BRONZE, 100％ → 100% | 2,771 | ①②③, ™, 한글 (전각 영문·숫자·기호만 바꿈) |
| 숫자 속 o → 0 | 1o,ooo → 10,000, SPF 5O → SPF 50, PEG-15O → PEG-150 | 273 | 4oz, CoQ10, Vitamin B3, Step 1 |
| 맨 앞 작은따옴표 제거 | ' shampooing → shampooing | 20 | 큰따옴표 "…" (진짜 인용일 수 있음) |

### 고치지 않은 것
| 문제 | 예시 | 이유 |
|---|---|---|
| 중간에 끼는 "1", "I" | in I Place, 1 appropriate | "Step 1", "1 pair of", "Should I"처럼 진짜 글자와 모양이 같아 구별 불가. 한 장에 1~2개 수준 |
| 필기체 오인식 | years → yeaus | OCR이 읽는 단계의 문제 (후처리로 불가) |
| 글자 누락 | 문장 일부를 못 찾음 | 위와 같음. 고치려면 OCR을 다시 돌려야 함 |

## 5. 한국어 이미지에 쓸 때

9월 올리브영 한국어 OCR 결과(31,737줄)에 이 코드를 시험했습니다.

- **순서 정리(1차·2차)는 그대로 쓸 수 있습니다.** 좌표만 보는 방식이라 언어와 상관없습니다.
- **겹친 글자·글자 보정은 한글을 건드리지 않습니다.** 영문·숫자만 대상입니다. 3차 보정으로 바뀐 줄은 18줄이었고 모두 맞게 고쳐졌습니다 (예: SPF 5O+ → SPF 50+).
- **한국어 고유의 문제는 잡지 못합니다.** 띄어쓰기 붙음, 한글 사이에 낀 선(`기|기`), 받침이 비슷한 글자 오인식 등. 한국어는 이 코드를 쓴 뒤 **따로 검수**하는 것을 권장합니다.
- 한국어 이미지는 `run_ocr.py`의 `REC_MODEL`을 `korean_PP-OCRv5_mobile_rec`로 바꿔서 실행합니다 (9월 올리브영 OCR에 쓴 모델).
- 참고: "한 글자 + 띄어쓰기"로 시작하는 한국어 줄(꼭 / 본 / 내 / 더 …)은 대부분 진짜 단어라서, 영어용 겹친 글자 규칙을 한국어로 넓히면 안 됩니다.
